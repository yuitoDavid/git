## 适用条件

- 每个环境独立求解同结构的有限时域 MPC。理想场景是 GPU 上有较多环境、预测步较多，并且 MPC 确实占训练时间。
- 公开实现共享状态转移矩阵 A，允许输入矩阵 B 随环境和预测步变动。步间强耦合约束、任意多面体、摩擦锥耦合、离散选点、非线性动力学和每步变化的 A 需要单独适配或扩展。
- JAX 公开接口给控制量逐步设箱约束，状态上下界实际用了大数。PyTorch 还接受共享的状态上下界。批量 PyTorch 路径对于逐步变化的 B，需关闭它自带的 precond。不要假定 setup 中每个参数在两条后端路径都生效。
- 这是一批彼此独立的求解。大量短时域也可能受 GPU 调度、同步、数据拷贝和显存争用影响。JAX 的固定 shape 会影响 JIT/AOT 编译复用情况。
- 本包使用 MPC 解作训练期参考的用法无需通过求解器反向传播。若目标是可微 MPC、真机在线安全控制或不同尺寸混合 batch，先定义额外的数值和验证要求。

## 本地运行

进入本目录。建议使用 Python 3.11 或 3.12 的独立虚拟环境。安装所选后端即可，两个 requirements 的框架版本取自作者仓库。GPU 版本按本机 CUDA、驱动和平台安装匹配的轮子。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-torch.txt
.\.venv\Scripts\python.exe scripts/smoke_mpc.py --backend torch --device cpu
```

Linux 或 WSL 用 .venv/bin/python。要用 JAX CPU，安装 requirements-jax-cpu.txt 后运行 python scripts/smoke_mpc.py --backend jax --device cpu。CUDA 已配置时可用 --device cuda，JAX CUDA 安装以[官方平台说明](https://docs.jax.dev/en/latest/installation.html)为准。PyTorch CUDA 版本见[官方安装页](https://pytorch.org/get-started/locally/)。

小算例使用带上下限的一维积分系统，检查求解后的初态误差、动力学残差、输入越界量和目标函数相对零控制的改善。预热计时等待 GPU 完成再计。它用于验证接线，机器人任务的性能应在目标数据和设备上另外验证。

## 接入接口

以下 E 是环境数，N 是预测步数，nx、nu 分别是状态、控制维数，ny 是 PyTorch 里由 C 定义的跟踪输出维数。

| 量 | 公共形状与含义 |
|---|---|
| A | (nx, nx)，状态转移，单次调用共享 |
| B_s | (E, N, nx, nu)，输入矩阵，可以分环境分预测步 |
| x0 / u0 | (E, nx) / (E, nu)，当前状态、上一控制输入 |
| e | JAX 使用 (E, nx)，在时域内广播。PyTorch 在 setup 用共享 e，solve_batch 用 (E, nx) 的 w 加上各环境偏置 |
| yref / uref | (E, ny, N) / (E, nu, N)，沿时域的参考。JAX 按状态直接跟踪，ny 等于 nx |
| Wy / Wu / Wdu / Wf | 状态或输出、输入、输入增量和末端二次代价矩阵 |
| umin_steps / umax_steps | (E, nu, N)，各环境和各预测步逐维上下界 |
| 结果 x / u | (E, nx, N+1) / (E, nu, N)，x 含初始状态。部署滚动 MPC 时第一步控制为 u[:, :, 0] |

PyTorch 训练栈从 vendor/pimpc.py 调用 Model.setup() 和 Model.solve_batch()。JAX 从 vendor/jax_pimpc.py 使用 PiMPCSolver(B, N, nx, nu) 与 solve(prob)。按脚本中的参数映射接入，常驻张量放在训练所用的设备上。不要把厂商机器人关节顺序和接触几何写进内核。

## 接入新任务与评估

1. 定义状态、控制量和参考轨迹，固定采样周期，并写出离散动力学。先用少量输入确认状态、控制和上一时刻输入的索引与单位。
2. 将任务代价和约束映射到张量接口，检查逐维上下界能否表达所需限制。共同进入同一批次的问题需共享 A，B 可按环境和预测步提供。
3. 选择输出用途。用于闭环控制时，将首步控制输入交给外部控制循环，由下一次观测滚动更新。用于训练时，可在每次求解后提取整段或部分参考，并接入奖励、critic 或蒸馏。

已有 MPC 时，用同一批实际输入做求解器 A/B 对照。对齐目标函数、可行性和约束后，比预热后批耗时、峰值显存、吞吐和长尾延迟。对每个环境独立计算残差和约束违规，JAX 的整批残差不能代替逐环境检查。实测端到端训练时另外计入生成动力学、跨框架张量转换、求解和奖励更新。

## 任务示例

- 轮式底盘速度跟踪。用速度作状态、加速度作输入，在固定采样周期下跟踪速度指令，对加速度设置逐维上下限。
- 机械臂关节跟踪。在指定工作点附近建立线性模型，用关节位置和速度作状态。按实际接口选择控制输入，并检查输入限幅和模型在目标运动范围内的误差。

### Walk the PLANC

PLANC 使用 LIP 解析步时、质心样条与 CLF 奖励，没有可直接替换的迭代 MPC。若研究训练参考质量，可先固定原来的下一块石头、落脚位姿和步时，只加入有预设接触序列的质心 MPC，再让它的质心预测作为 CLF 的参考。比较原样条与 MPC 两组的落脚误差、受扰通过率和训练墙钟时间。现成 πⁿMPC 不直接处理离散选石或联合优化换脚时刻。 [PLANC §III](https://arxiv.org/html/2601.06286v1#S3)
